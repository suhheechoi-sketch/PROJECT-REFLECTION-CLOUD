현재 GitHub 저장소의 PROJECT: REFLECTION T/A DEMO를 개선하십시오.

2. 레이저 관측 카메라 시스템

2.1 현재 문제

현재 게임에서 플레이어가 레이저를 발사하면 광선이 화면 밖으로 진행하는 경우가 있습니다.

이때 플레이어는 다음 사항을 파악하기 어렵습니다.

* 레이저가 어디까지 진행했는가?
* 어느 벽이나 장치에 충돌했는가?
* 거울에서 반사된 이후 어디에 도달했는가?
* 수신기에 정상적으로 도달했는가?

이 문제를 해결하기 위해 새로운 레이저 관측 시스템을 구현하십시오.

2.2 기본 설계

메인 카메라는 기존 플레이어 중심 시점을 유지하십시오.

메인 카메라가 레이저를 따라 이동하는 방식은 사용하지 마십시오.

대신 별도의 보조 카메라를 이용하여 레이저의 마지막 충돌 지점을 보여주는 작은 관측 화면을 구현하십시오.

관측 화면은 화면 오른쪽 위에 배치하는 것을 기본으로 하되, 기존 UI와 겹치지 않도록 조정하십시오.

첨부 PDF의 레이저 관측 화면 목업을 참고하십시오.

2.3 관측 화면 활성화 조건

다음 조건을 만족할 때 관측 화면을 표시하십시오.

1. 플레이어가 레이저를 발사하고 있습니다.
2. 실제 광선의 마지막 지점이 메인 카메라 화면 밖에 있습니다.
3. 관측할 수 있는 유효한 광선 경로 데이터가 존재합니다.

반대로 다음 상황에서는 관측 화면을 표시하지 마십시오.

* 레이저가 화면 안에서 끝나는 경우
* 플레이어가 레이저를 발사하지 않는 경우
* 광선 경로가 존재하지 않는 경우
* 게임이 일시 정지된 경우
* A구역 콘솔 카메라가 활성화된 경우

다만 발사기 거치로 지속 발사되는 광선은 해당 퍼즐의 실제 플레이 상황을 고려하여 별도로 처리할 수 있습니다.

2.4 관측 카메라의 작동 방식

관측 카메라는 레이저의 실제 계산 결과를 이용해야 합니다.

기존 scripts/laser_system.gd를 분석하십시오.

현재 레이저 시스템의 _trace()는 실제 충돌 및 반사 경로를 계산하고, 광선 세그먼트를 생성합니다.

이 정보를 재사용하십시오.

별도의 레이캐스트 시스템을 만들어 기존 광선과 서로 다른 경로를 계산해서는 안 됩니다.

단계 1 — 광선 경로 데이터 확보

실제 광선 계산 결과에서 다음 정보를 얻으십시오.

* 광선 세그먼트 시작점
* 광선 세그먼트 끝점
* 광선의 채널 및 세기
* 충돌 여부
* 충돌한 장치의 종류
* 반사 횟수
* 분기된 광선의 식별 정보

필요하다면 laser_system.gd에 관측 전용 데이터 구조를 추가하십시오.

단, 기존 광선 판정과 수신기 활성화 기능을 변경하지 마십시오.

단계 2 — 마지막 충돌 지점 확인

광선이 여러 거울에서 반사되더라도 실제 계산된 마지막 지점을 추적해야 합니다.

예를 들어 다음 경로가 존재한다고 가정합니다.

광원기 → 거울 A → 거울 B → 벽

관측 카메라는 최초 광원기나 거울 A를 보여주는 것이 아니라, 마지막으로 광선이 도달한 벽을 보여주어야 합니다.

단순히 레이저가 처음 발사된 방향으로 카메라를 이동시키는 방식은 허용하지 않습니다.

단계 3 — 카메라 위치 계산

관측 카메라가 다음 두 요소를 함께 보여주도록 구도를 계산하십시오.

1. 레이저의 마지막 지점
2. 마지막 지점에 도달하기 직전의 광선 구간

이를 위해 마지막 세그먼트의 시작점과 끝점을 활용하십시오.

관측 카메라의 중심은 마지막 충돌 지점에 조금 더 가깝게 배치하되, 직전 광선의 진행 방향을 확인할 수 있어야 합니다.

카메라의 시점은 기존 게임의 탑다운 또는 쿼터뷰 구도와 일관되게 유지하십시오.

단계 4 — 화면 밖 판정

메인 카메라에서 광선의 마지막 지점이 보이는지 계산하십시오.

Godot의 Camera3D 화면 좌표 변환 기능을 활용할 수 있습니다.

광선의 마지막 지점이 화면 안에 있다면 관측 화면을 표시하지 마십시오.

화면 밖에 있다면 관측 화면을 표시하십시오.

카메라 경계에서 광선이 조금씩 움직일 때 관측 화면이 반복적으로 나타났다 사라지는 현상을 방지하십시오.

단계 5 — 관측 화면 렌더링

Godot의 다음 기능을 활용하는 방식을 우선 검토하십시오.

* SubViewport
* Camera3D
* SubViewportTexture
* TextureRect
* CanvasLayer

관측 카메라가 기존 게임 월드를 촬영하고, 그 결과를 화면 오른쪽 위의 작은 UI에 표시하도록 구현하십시오.

관측 화면에는 다음 정보를 표시할 수 있습니다.

BEAM OBSERVER

WALL CONTACT

MIRROR CONTACT

RECEIVER ACTIVE

단, 실제 광선 계산 결과와 일치하는 정보만 표시하십시오.

실제로 수신기에 도달하지 않았는데 수신기 활성화를 표시해서는 안 됩니다.

2.5 광선 분기 처리

기존 게임에는 빔 스플리터 및 분광 장치가 포함될 수 있습니다.

따라서 광선이 여러 갈래로 나뉘는 상황도 고려해야 합니다.

관측 화면은 기본적으로 하나만 표시하십시오.

여러 광선이 동시에 존재한다면 다음 기준으로 관측 대상을 선택하십시오.

1. 플레이어가 직접 발사한 광선을 우선합니다.
2. 실제 수신기에 도달한 광선을 우선적으로 고려합니다.
3. 화면 밖에 존재하는 실제 충돌 지점을 선택합니다.
4. 동일한 조건이라면 일관된 우선순위에 따라 선택합니다.

관측 대상이 지나치게 자주 변경되지 않도록 안정화 처리를 적용하십시오.

2.6 관측 화면 종료

레이저 발사를 중단하면 관측 화면을 즉시 제거하지 말고 약 0.6~1.0초 동안 유지한 후 자연스럽게 사라지도록 구현하십시오.

다만 퍼즐 완료, 콘솔 진입, 게임 종료 등의 상태에서는 필요에 따라 즉시 숨길 수 있습니다.

2.7 성능 최적화

현재 게임은 PC뿐 아니라 iPad Safari에서도 실행됩니다.

따라서 관측 카메라의 렌더링 비용을 최소화해야 합니다.

다음 사항을 고려하십시오.

* 낮은 해상도의 SubViewport 사용
* 필요할 때만 관측 카메라 활성화
* 관측 화면의 업데이트 빈도 제한
* 불필요한 후처리 효과 제거
* 기존 월드 및 광학 장치 데이터 재사용
* 모바일 환경에서 메모리 사용량 최소화

초기 관측 화면 해상도는 256×144 또는 320×180 정도를 검토하십시오.

실제 기기에서 성능을 확인한 후 조정하십시오.

만약 실시간 관측 카메라의 성능 부담이 지나치게 크다면, 실제 충돌 위치와 직전 광선 정보를 표시하는 간단한 2D 관측 패널을 대체 방식으로 검토하십시오.

단, 구현하지 않은 실시간 카메라를 구현한 것처럼 보고하지 마십시오.

3. 기존 카메라 시스템 유지

이번 작업에서는 V키를 이용한 별도의 퍼즐 관찰 모드를 추가하지 마십시오.

일반 탐색에서는 기존 플레이어 중심 카메라를 유지합니다.

A구역의 광학 제어 콘솔에 상호작용했을 때 퍼즐 전체를 보여주는 카메라 기능은 그대로 유지하십시오.

정리하면 다음과 같습니다.

* 일반 탐색: 플레이어 중심 카메라
* 레이저 발사: 필요할 때 작은 관측 화면 표시
* T구역: 기존 방식으로 거울 직접 조작
* A구역: 콘솔에서 거울 원격 조작
* 콘솔 종료: 플레이어 중심 카메라 복귀

기존 V키가 별도의 전체 보기 기능으로 사용되고 있다면, 이번 설계에 맞게 해당 기능의 필요성을 검토하고 일반 탐색용 관찰 모드로 남기지 마십시오.

⸻

4. 광학 장치 디자인 개선

첨부 PDF의 광학 장치 콘셉트 이미지를 참고하십시오.

기존 게임의 광학 장치는 기능적으로 작동하지만, 외형이 단순하여 장치의 역할을 구분하기 어렵습니다.

다음 장치의 외형을 개선하십시오.

4.1 휴대용 레이저 발사기

* 산업용 광학 장비 형태
* 두꺼운 금속 프레임
* 발광 렌즈
* 에너지 상태 표시등
* 기존 PS1 로우폴리 스타일 유지

4.2 회전형 거울

* 명확한 반사면
* 금속 회전축
* 각도 눈금
* 회전 가능한 방향 표시
* 선택 상태 강조

4.3 광학 수신기

* 방향성 렌즈
* 수신 방향 표시
* 비활성 및 활성 상태 구분
* 광선 수신 시 발광 효과

4.4 광학 제어 콘솔

* 산업용 금속 제어 장치
* CRT 스타일 모니터
* 물리 버튼 및 스위치
* 케이블 연결 구조
* 상호작용 상태 표시

4.5 레일형 거울

* 바닥 레일
* 이동 가능한 거울 프레임
* 레일 잠금장치
* 이동 방향 표시

장치의 외형을 개선하더라도 기존 광학 충돌 판정과 퍼즐 기능은 유지하십시오.

5. 게임 환경 디자인 개선

PROJECT: REFLECTION의 목표 분위기는 산업 공포, 디스토피아, PS1 로우폴리 스타일입니다.

첨부 PDF의 환경 디자인 이미지를 참고하십시오.

T구역

* 비교적 밝고 정돈된 실험실
* 광학 장치가 잘 보이는 조명
* 단순한 산업용 벽과 바닥
* 명확한 구역 표시
* 튜토리얼에 적합한 높은 가독성

A구역

* 낡고 복잡한 산업 실험 시설
* 금속 벽과 바닥
* 노출된 배관과 케이블
* 마모 및 오염 표현
* 경고 표지와 장치 번호
* 제한적인 조명과 그림자

단, 분위기를 위해 화면을 지나치게 어둡게 만들지 마십시오.

광학 퍼즐에서 거울, 수신기, 광선의 식별 가능성이 가장 중요합니다.

이번 작업에서는 새로운 DIRECTOR 대사, 추격 시스템, 점프스케어, 스토리 이벤트를 추가하지 마십시오.

⸻

6. UI 및 글씨 개선

현재 게임의 글씨는 다소 작고 가늘게 보입니다.

다음 방향으로 개선하십시오.

1. 현재보다 글씨를 조금 더 굵게 만듭니다.
2. 본문과 상호작용 안내의 크기를 소폭 확대합니다.
3. 한국어와 영어의 가독성을 모두 확인합니다.
4. 산업 시설에 어울리는 기계적인 UI 스타일을 유지합니다.
5. 텍스트와 배경의 명도 대비를 개선합니다.
6. 장치 이름과 안내 문구가 겹치지 않도록 배치합니다.

전체 글씨를 과도하게 굵게 만들지 마십시오.

중간 굵기를 기본으로 하고, 경고 문구나 주요 제목만 선택적으로 강조하십시오.

특히 iPad Safari에서 글씨가 잘리거나 버튼과 겹치는 문제가 없는지 확인하십시오.

⸻

7. 퍼즐 완료 피드백 개선

현재 퍼즐 완료 시 플레이어가 성공 여부를 더욱 명확하게 확인할 수 있도록 시각적·청각적 피드백을 추가하십시오.

다음 순서로 연출하십시오.

1. 광학 수신기 활성화
2. 수신기 렌즈 발광
3. 전력 케이블을 따라 빛이 이동
4. 문 잠금장치 해제
5. 문 개방 및 기계 작동음 재생
