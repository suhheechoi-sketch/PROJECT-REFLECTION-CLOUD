# T/A 광학 콘솔 및 T03 지정 차폐실 수정

기준 main `860906b` / Godot **4.7.2.stable.official.ed1daf0bf**, Compatibility.
사용자가 첨부한 Safari 화면의 표시와 붙여넣은 요청을 기준으로 수정했다. 기존 전체 시설 씬과 T/A의 장치 위치·해답·광학·진행·체크포인트를 유지한다. main에는 직접 병합하지 않는다.

## 1. 정확히 제거한 구조

실행 씬 `scenes/ta_demo.tscn` → `scripts/ta_geometry.gd`의 추가 수신기 차폐실 중 **T-03만** 생성을 생략한다. 입력 JSON/원본 설계는 보존한다.

수신기 `T03-RN`은 **(39,0,5)**에서 그대로 작동한다. 제거한 별도 사각 구획은 **x=37~41, z=3~8**이다.

| 제거한 선분 (x,z) | 종류 |
|---|---|
| (37,3)→(41,3) | 벽 |
| (41,3)→(41,8) | 벽 |
| (37,8)→(41,8) | 벽 |
| (37,3)→(37,4.75) | 벽 |
| (37,5.25)→(37,8) | 벽 |
| (37,4.75)→(37,5.25) | 몸만 차단하던 광학 창 |

모델뿐 아니라 해당 **6개 물리 충돌체**도 생성하지 않는다. 다른 방의 사각 구획은 추측하여 제거하지 않았다. 거울과 수신기를 함께 감싸는 **ㄱ자 광학 통로**, T03 방 외곽(일부 제거 선분과 같은 x=41의 시설 외벽 포함), 다른 T/A 벽·문·수신기는 유지한다.

변경 전 main의 구조 충돌체 목록에서 지정된 6개만 제외한 뒤, 나머지 **264개**의 위치/크기/층을 비교한 SHA256은 `d8a84e7080a6455152f4b2e33485dbe5765a12467cf380b36247fd68b526673c`다. 수정 후 같은 해시를 검사한다. 별도의 콘솔 가구는 이 벽 목록에 포함되지 않는다. 기존 T03 최소 반사 1회 조건도 유지한다.

## 2. 콘솔과 조작

| 구역 | 콘솔 위치 (x,z) | 구현 |
|---|---|---|
| A01 | (36,45), 기존 위치 | 기존 즉시 E 진입을 재사용하고 외형·시점·선택을 보강 |
| A02 | (9,46), 기존 위치 | 기존 거치/레일 스크립트를 재사용하고 콘솔 외형·시점·선택 보강 |
| A03 | **(9,75), 신규 콘솔** | 보행 가능한 서비스 공간에 콘솔 추가; 일반 거울 4개를 여기서 조작 |

새 `scenes/optical_console.tscn`과 `scripts/ta_console_station.gd`는 금속 하우징, CRT, 버튼·상태등, **OPTICAL CONTROL / 광학 제어 콘솔** 표식을 제공한다. 근접/조작 중 상태등이 변하고 HUD에 E/조작 안내를 표시한다. 기존 장치 중심과 레일 범위는 옮기지 않았다.

**A 일반 거울은 콘솔 모드에서만 선택**한다. T 튜토리얼의 근접 E 학습과 A02/A03의 현장 레일 손잡이는 유지한다. 고정 각도의 레일을 콘솔에서 회전시키지 않는다.

- E / 터치 조작: 즉시 콘솔 진입. 추가 V 입력 없음.
- 거울 클릭/터치: 해당 구역의 조작 가능한 일반 거울 선택. 외곽 강조·이름·각도 표시.
- 휠 / +·−: 15°, Shift+휠 / 1° 버튼: 정밀 1°.
- 바닥·빈 공간·선택 불가 장치 클릭: 선택만 해제. 콘솔은 유지하며 재선택 가능.
- HUD 및 터치 버튼: 선택 해제를 일으키지 않는다. 미선택 상태의 회전은 무시하고 버튼을 어둡게 표시한다.
- Esc / 종료: 선택·조작 UI를 해제하고 저장한 탐색 카메라로 복귀. 각도·수신기 래치·완료 진행은 초기화하지 않는다.

A01/A03의 **F / 출력**은 현재 위치에서 플레이어가 소유한 **실제 L-07**을 조사한다. 조준점과 동일한 기존 레이캐스트 엔진을 사용해 회전 중 반사 경로/수신 판정이 갱신된다. 발사 패드에서 콘솔에 접근 가능한 경우에는 그 위치에서 그대로 조사할 수 있다. 콘솔 위치에서 광로가 벽에 막히면 실제로 막히며 정답 경로로 빛을 순간 이동시키지 않는다. 콘솔 종료 시 일반 휴대 발사 조작으로 돌아간다. A02는 기존 거치광이 콘솔 중에도 계속 조사된다. 추가 고정 광원이나 광학 장치를 만들지 않는다.

## 3. 카메라 및 터치

`ta_console_view.gd`는 기존 A01 V-view와 같은 내려다보는 방향을 사용한다. 퍼즐 중심/장치·발사 경로 범위를 PC 16:9와 4:3 화면의 사용 가능 영역에 맞춘다. 진입 시 미니맵을 잠시 숨기고 종료 때 사용자의 이전 표시 상태를 복원한다. 구조물은 콘솔 관찰 중 시각적으로만 옅어지며 물리 충돌은 유지된다. 이 변경은 T03의 명시적 제거 외에 벽을 삭제하는 기능이 아니다.

콘솔 중 터치 이동·일반 발사 버튼을 숨기고 하단에 **− / + / 1° / 출력 / 종료**를 배치한다. A02에서는 거치 기능의 기존 출력 규칙을 유지한다. 터치 선택에는 화면상 약 56px 지름의 보조 영역을 제공한다. 실제 광학 콜라이더를 확대하지 않으며 PC 레이 선택은 그대로다. 포커스/크기/모드 변경 시 손가락 유지 상태를 해제한다.

증거: `console_evidence/`의 로그와 PNG. `--visual-review`는 스크립트가 E/클릭/터치 입력을 보내고 실제 프레임을 촬영한 **자동 렌더 검사**다. 사진 이름의 ipad_ratio는 4:3 비율을 뜻하며 실제 iPad 촬영을 뜻하지 않는다.

재현:

```bash
GODOT=/path/to/godot-4.7.2 ./VERIFY_REFLECTION.sh --import
godot --path . --script res://tests/console_interaction_test.gd -- --visual-review
godot --headless --path . --export-release Web work/web/index.html
python tests/validate_web_export.py work/web
CHROMIUM_PATH=/usr/bin/chromium python tests/web_smoke.py
```

Windows 검증 스크립트에도 터치/새 콘솔 suite와 렌더 검사를 추가했지만 Windows 자체 실행은 미검증이다.

## 5. 남은 검증·제한

실제 iPad Safari의 새 콘솔 전체 조작·기기 터치 감각·세로 화면·오디오 청취 및 사람이 시작부터 끝까지 완주하는 것은 **미검증**이다. Chromium 브라우저 검사는 부팅/기본 멀티터치 범위이며 콘솔 전 과정을 Safari에서 완료했다는 뜻이 아니다. PC/4:3 콘솔 전 과정은 native Godot에서 자동 입력으로 검증했다. 렌더 종료 때 기존 WAV 관련 ObjectDB 2개 정리 경고가 남는다. 연속 공간의 모든 우회나 모든 해상도를 증명한 것은 아니다.

이 PR은 main에 직접 병합하거나 배포하지 않는다. 현재 공개 사이트는 병합 전 버전이며 새 동작은 PR 브랜치의 게임과 CI 웹 아티팩트에 들어 있다.
