# 카메라·공간 표시 진단 (2026-10-25)

복구 커밋: `0fce368`, 태그: `rendering-before-20261025`. 작업 전에 존재하던 변경과 신규 파일을 함께 보존했다. 기존 `v3-before-v4-quality` 태그는 유지했다.

## 확인한 원인과 범위

- `main.gd::_build_player_and_camera`, `QuarterViewCamera`: 기존 pitch -65°, 로컬 위치 (0,6,0)는 기울어진 광축의 바닥 교점을 플레이어에 맞추지 않았다. 1920×1080에서 인물 높이 1m의 투영 좌표는 (960,687.23)이었다. 수정 후 (960,516.17)이다. 이동 입력에 따른 카메라 회전 코드나 중복 추적 코드는 없었다. 플레이어는 회전하지 않고 발사기 메시만 조준 방향으로 회전한다.
- `room_occlusion.gd::add_room/refresh`, `UnseenRoomMask_*`: 실제로 겹치는 방 사각형을 그대로 검게 덮었다. 예를 들어 hub 범위는 T 구역 일부와 겹친다. 현재 방 마스크가 꺼져 있어도 다른 방 마스크가 그 영역에 남을 수 있었다.
- `main.gd::_register_room_visuals`: 여러 방에 걸치는 바닥 슬래브도 중심점 하나로 방에 배정하고 전체를 숨겼다. 공유 바닥은 이 처리에서 제외했다.
- 방 공개 전환 tween은 빠르게 상태를 바꾸면 이전 tween과 경합할 수 있었다. 새 tween 전에 이전 것을 중단한다.
- 환경 fog는 이미 꺼져 있었고, 발견 셀 기반 3D 암전은 없었다. 탐색 셀은 미니맵/Tab에만 쓰인다. 기존 벽 투명화 시스템도 없었다.
- 구조벽·시설 장식·광학 장치 그림자는 이미 비활성화되어 있었다. 방향광은 켜져 있어 플레이어 등의 일반 그림자는 남는다. 그림자 전체를 영구 제거하지 않았다.
- 후처리는 고정 화면 디더링·양자화·비네트다. 시간 노이즈나 카메라 흔들림은 없지만 nearest 텍스처와 화면 고정 디더링으로 생길 수 있는 이동 중 픽셀 변화는 이번에 제거하지 않았다.

## 독립 테스트

포함된 Godot 4.7.2 / Compatibility / GTX 1060으로 `tests/render_diagnosis.gd`를 실행했다. 각 실행은 새 씬을 만들고 전용 탐색 저장 경로를 사용한다. 실제 게임 설정에 테스트 스위치를 남기지 않는다.

| 테스트 | 실행 및 관찰 | 해석의 한계 |
|---|---|---|
| A | 마스크·방별 메시 숨김·방별 조명 숨김만 해제. 문 주변과 상단의 검은 바닥 영역이 변함 | 닫힌 방의 의도한 검정도 함께 제거되므로 모든 검정이 오류라는 뜻은 아님 |
| B | 모든 Light3D 그림자만 해제. 인물·소품 그림자는 사라지고 방 마스크는 유지 | 일반 그림자를 검은 방 마스크의 원인으로 보지 않음 |
| C | 기존에는 벽 투명화 구현이 없어 비활성화 대상 없음. 원본과 같은 상태로 렌더링 | 원본의 갑작스러운 벽 변화가 벽 투명화 때문이었다고 주장할 수 없음 |
| D | 카메라를 월드에 reparent하고 보간 해제 후 동일 위치를 렌더링 | 정지 포즈 비교이며 이동 영상 기반 흔들림 비교는 아님 |

각도 65/70/75°를 같은 위치에서 렌더링했다. 70°는 바닥·인물 가독성을 높이면서 75°보다 벽 옆면을 더 남겨 선택했다. 최종 Euler (-70°,0°,0°), 위치 (0,8,8/tan70°), 직교 size 15.5다. 플레이어 자식 관계와 엔진 물리 보간을 유지하고 별도 추적 보간은 추가하지 않았다. 이동 속도와 가속도도 유지했다.

## 처리 방법

공간 표시는 기존 문 연결 그래프와 실제 CollisionShape3D.disabled 상태로 BFS한다. 열린 우회 경로도 공개된다. 닫힌 방의 검은 바닥 메시에서 현재 연결된 모든 방의 사각 범위를 잘라낸다. 마스크는 낮은 평면이며 충돌체나 카메라 앞 볼륨을 만들지 않는다. 기존 방 범위와 그래프 자체는 재설계하지 않았다. 미니맵의 발견 셀, 문 표식, 방향, 목표 및 Tab 지도 코드는 수정하지 않았다.

`wall_visibility.gd`는 구조벽과 얇고 높은 시설 분리벽만 수집한다. 직교 카메라 방향으로 인물의 높이·좌우 표본 9개의 선분과 벽의 로컬 AABB를 검사한다. 가리면 개별 복제 재질의 alpha를 0.15까지 지수적으로 전환하고, 해제되면 원래 alpha로 돌린다. GeometryInstance3D.transparency를 쓰는 방 공개와 다른 속성을 사용한다. 벽 노드·위치·충돌층·Shape3D·광학 계산은 변경하지 않는다.

- 기존 런타임 시작 및 12개 자동 검증 묶음 통과. 광학·대표 퍼즐·챕터 진행·길찾기·미니맵 탐색·원본 자산 해시 포함.
- 새 `camera_motion_test.gd` 통과: 실제 주입한 D, D+S, A 입력으로 이동했음을 확인하고 매 물리 프레임의 카메라 상대 위치·회전, 정지 후 위치, 벽 alpha 감소·복원 및 동일 충돌 Shape3D를 검사했다. headless 실행이다.
- 갱신한 `room_visibility_test.gd` 통과: 문 개방, 물리적으로 닫힌 문, 열린 우회로, 충돌 보존, 미발견 미니맵 셀 유지, 검은 메시 삼각형 중심이 공개된 영역을 침범하지 않음을 검사했다.
- 수정 후 기존 8개 시각 검수 포즈를 GPU로 렌더링했다. `tools/validation/v5_1_review/`에 저장된다. 이 포즈는 테스트용 상태 변경과 순간이동이며 정상 플레이 완료 증거가 아니다.
- 수정 전후 동일 위치: `artifacts/before_rendering.png`, `artifacts/diagnosis_after.png`. A–D 및 각도별 비교도 artifacts에 보존했다.
- 제한된 실행 환경의 인증서 저장소 경고가 headless에서 발생했다. 프로젝트 SCRIPT ERROR나 테스트 실패는 없었다.

## 남은 검증과 제한

원래 녹화 영상·스크린샷 파일은 제공되지 않아 해당 영상의 모든 검은 삼각형 원인을 동일하게 재현했다고 말할 수 없다. 프레임레이트를 바꾼 장시간 이동 영상, 전체 시설의 모든 벽 앞 수동 보행, 수동 문 조작 반복 검수는 수행하지 않았다. GPU 검수는 정지 포즈이며 프레임 간 체감 떨림의 완전 제거를 입증하지 않는다.

공간 가림은 기존 사각 방 정의를 기반으로 한다. 현재 방과 겹친 검은 영역은 제거하지만 전체 맵의 모든 방 경계가 실제 벽과 일치하는지는 추가 수동 검수가 필요하다. 이 검증을 위해 맵을 새로 만들거나 방 좌표를 추정해서 바꾸지 않았다. 높은 문틀·랙·광학 장치는 벽 투명화 대상이 아니므로 이들이 가리는 모든 상황까지 해결한 것은 아니다. alpha 재질끼리의 깊이 정렬과 nearest 표면의 이동 중 모아레도 모든 시점에서 보장하지 않는다.

수정 파일: `scripts/main.gd`, `scripts/room_occlusion.gd`, 신규 `scripts/wall_visibility.gd`, `tests/room_visibility_test.gd`, 신규 `tests/camera_motion_test.gd`, 신규 `tests/render_diagnosis.gd`, `VERIFY_REFLECTION.ps1`, 본 보고서 및 비교 PNG. 맵 생성 좌표, 퍼즐·광학·진행·플레이어 이동 스크립트, 잠금 원본 자산은 수정하지 않았다.
