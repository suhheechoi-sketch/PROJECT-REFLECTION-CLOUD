## 이미 동작하는 기능

- 플레이어 WASD 이동, 쿼터뷰 카메라, 마우스 바닥 조준, 좌클릭 광선 발사.
- 실제 충돌 표면을 이용한 거울 반사, 굴절 매질 통과, 백색광의 프리즘 RGB 분산, 스플리터 분기.
- 거울·매질·프리즘·스플리터를 E로 선택하고 휠로 15° 회전. 회전 시 보이는 장치와 물리 충돌 표면을 명시적으로 동기화한다.
- 수신기의 광량 최소값·색상·방향·지속 시간을 판정하고 활성화 발광으로 표시한다.
- 회전 차단막의 통과·정지 동작, 목표 HUD, H/F1 조작 도움말, Tab 구역 해금 현황, 주변 장치 강조.
- T-01 이동, T-02 일반 수신기, T-03 한 번 반사, T-04 두 거울 연속 반사로 진행되는 튜토리얼.
- 중앙 배광실 기본 블록아웃과 T·A·H·B·C 방향의 물리 문, 진행 조건 데이터.

## 핵심 차이와 미구현 범위

1. **광증폭 시스템:** 현재 입력 광량은 1.0(100%)이고 증폭 장치가 없다. `medium`은 굴절만 한다. 최종 설계의 G-01은 매질을 지나 2.0배, 상한 3.0배까지 에너지를 높이는 장치로 교체·확장해야 한다.
2. **프리즘 광량:** 현재 백색광 진입 때 RGB 가지를 만들고 각각 `energy / 3`으로 보낸다. 색상 분산 원리는 있으나 증폭기와 결합한 고출력 조건은 없다.
3. **스테이지 완성:** T-01~T-04는 진행 가능하다. A-01과 B-02, C-01/C-02는 장치·광로 시제품이다. stage JSON에 적힌 성공 판정·게이트·보상·스토리 중 일부는 아직 장치 신호와 연결되지 않았다. A-02/A-03, B-01/B-03, C-03, D/E/F는 예정 단계다.
4. **허브 변화와 탐색:** 주요 허브/문/색이 다른 바닥 구획이 있지만 회로 복구에 따른 기계 애니메이션·조명 변화, 개방되는 B-C 지름길, 완성된 벽/세부 공간은 없다. Tab 지도는 상태 텍스트 요약이지 플레이 가능한 시설 지도 화면이 아니다.
5. **스토리와 메타 진행:** DIRECTOR 방송은 목표용 문구와 반응 몇 개로 제한된다. 감시 AI, 기록 단말기 UI, 기록 수집으로 E를 여는 실제 경로, 강제 장치 제어, 보스전 및 엔딩은 미구현이다.
6. **완성도:** 저장·불러오기, 효과음/음악, 완성 환경 모델·텍스처, 접근성·키 재설정, 전체 게임 플레이 밸런스는 남아 있다. 현재 프로젝트는 절차형 회색상자 플레이어블 프로토타입이다.

## 이번 범위에서 실제 추가·수정한 점

- 사용자가 준 v3 원문을 `docs/MASTER_PROMPT_V3.md`로 보존하고, 이전 문서의 구식 T-04 연결 복도 설계 및 폐쇄 구역 조건을 현재 기준으로 교체했다.
- 19단계 데이터와 간단 검증기를 추가했다. 런타임 튜토리얼 단계명과 단계 조건은 이 카탈로그를 참조한다.
- 기존 `hidden_circuit_found` 한 개 불리언 대신 비인가 수신기 ID 목록과 `D-EMERGENCY_CONTROL` 기록을 따로 관리한다. 폐쇄 구역 해금은 서로 다른 비인가 수신기 두 개와 비상 기록을 모두 요구한다.
- T-04를 통과형 복도에서 실제 두 번 반사 검사로 바꿨다. 단계별 수신기 활성화와 문 해금, 튜토리얼 완료 후 짧은 허브 카메라 공개 연출을 연결했다.
- 입력 직후 거울 각도와 물리 충돌체 각도가 어긋나던 문제를 수정했다. 회전·초기화 시 `PhysicsServer3D`의 본체 변환을 업데이트하도록 해 광선이 실제 표시 각도에 반사된다.
- 튜토리얼 목표 문구와 허브 진입 조건을 새 진행에 맞췄다.

## 검증 항목과 한계

자동 검증은 프로젝트에 포함된 `tests/optics_math_test.gd`, `tests/progression_state_test.gd`, `tests/stage_catalog_test.gd`, `tests/tutorial_flow_test.gd`로 한다. 특히 튜토리얼 흐름 검증은 실제 광선 발사 함수와 충돌 물리로 T-02, T-03, T-04 수신기를 켜고 두 거울 반사·게이트 해금을 확인한다.

이번 변경 후 네 자동 검증이 모두 통과했다. Godot 4.7.2 헤드리스 편집기 초기 스캔도 스크립트 클래스 등록까지 완료했고, `PLAY_REFLECTION.bat`으로 일반 게임 창을 실행해 `PROJECT: REFLECTION (DEBUG)` 창이 응답 중인 것을 확인했다.

검증 실행 환경에서는 사용자 프로필의 Godot 로그·편집기 캐시 폴더 쓰기와 Windows 루트 인증서 저장소 읽기가 제한되어 관련 오류 메시지가 출력됐다. 프로젝트 스크립트 오류는 아니며, 자동 검증은 완료되어 통과했다. 사용자가 일반 Windows 세션에서 실행할 때는 Godot가 사용자 폴더에 캐시와 로그를 쓸 수 있어야 한다.

이 검증은 회색상자 동작을 자동 확인한다. 전체 키보드·마우스 조작감, 화면 가독성, 모든 A/B/C 퍼즐의 해결성, 그래픽 품질은 별도 직접 플레이테스트가 필요하다.

## 다음 개발 순서

1. T-01~T-04를 일반 창에서 키보드·마우스로 직접 플레이하며 카메라, 프롬프트, 광선 시작점, 문 통과를 확인한다.
2. A-01~A-03을 독립 회로로 마무리하고 회로 A 복구만 B/C 문을 열도록 한다.
3. 광량 값을 가지별로 추적하는 G-01 증폭 규칙(100%→200%, 최대 300%)과 고출력 수신기를 추가하고 B-01~B-03에 연결한다.
4. C-01의 증폭 후 50:50 분기, C-02의 차단막 제어·2초 유지, C-03의 동시 동기화 조건을 완성한다.
5. D 기록 UI·해금, 비인가 경로, 세이브/로드와 B-C 지름길을 구현한다.
6. E에서 DIRECTOR의 규칙 기반 방해를 추가하고 F-01/F-02와 엔딩 A/B를 완성한다.
7. 환경 세부와 사운드를 보강하고 전체 순회 플레이테스트를 한다.
