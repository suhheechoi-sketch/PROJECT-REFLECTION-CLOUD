# A-01 광학 제어 편의성 개선

2026-10-25 / Godot 4.7.2 Compatibility. 작업 전 상태는 커밋 `b69d4c9`에 보존했다.

## 사용법

1. A-01 중앙 점검 동선의 기존 콘솔(월드 X=-55, Z=17.8)에 접근해 **E**로 연결한다. 콘솔 위에 ‘광학 제어 콘솔’ 표식과 연결 표시등을 추가했다. 새 충돌체나 광원 발사 장치는 만들지 않았다.
2. **V**로 기존 퍼즐 전체 보기를 켠다. 연결 후에는 A-01 내부 어디서나 원격 조작할 수 있다.
3. 거울 위에 커서를 올리면 반사면·기존 표시등과 M1/M2/M3 화면 표식이 강조된다. **E**로 선택하거나 다른 거울로 선택을 바꾼다.
4. **휠**은 기존 15°, **Shift+휠**은 기존 1° 회전이다. 작은 선택 카드에 거울 번호·각도·조작법만 표시한다.
5. **Esc**는 선택 해제, 선택이 없으면 광학 제어 보기를 종료한다. 이후 Esc는 기존 일시정지다. V로도 탐색 보기에 복귀할 수 있다.

기존 근접 E 조작도 유지한다. 콘솔 권한은 방 ID별 사전에 저장하며 이번에 활성화할 수 있는 방은 A01 하나다. 로컬 R 초기화와 방 이탈/재진입에는 권한이 유지되고, 게임 전체 재시작인 Shift+R에는 초기화된다. 권한의 디스크 영구 저장은 추가하지 않았다.

## 구현과 범위 제한

- 기존 `CONTROL CONSOLE`의 위치·메시·충돌을 재사용한다. 연결 시 거리 2.7m와 기존 플레이어 시야 검사를 통과해야 한다. 물리적으로 A-01에 있어야 권한을 얻고 사용할 수 있다.
- 원격 선택은 권한 + 현재 방 + V 전체 보기 조건을 확인한다. 현재 카메라에서 쏜 실제 3D 레이와 기존 충돌 마스크 2|4를 이용해 첫 충돌 물체를 고른다. 해당 물체가 **A-01 소유 거울 3개의 명시적 목록**에 있어야 선택한다. 수신기·다른 방 거울·화면 밖 대상은 선택할 수 없다. 벽도 레이 선택을 가로막는다.
- UI 패널 위에서는 E 선택과 휠을 차단한다. Tab 지도·도움말·로그·일시정지 중에도 원격 입력을 막는다. Tab을 닫으면 기존 선택을 이어 쓸 수 있다.
- 원격으로 선택된 A-01 거울에만 기존 근접 거리/시야 제한을 면제한다. 다른 장치와 일반 근접 조작의 거리 규칙은 유지한다. 방이나 전체 보기에서 나가면 원격 선택을 해제한다.
- `camera_pointer.gd`는 현재 투영 행렬과 보간된 카메라 변환으로 화면 좌표를 월드 광선으로 바꾼다. 기존 플레이어 조준과 원격 선택이 이 함수를 함께 쓴다. 마우스 이벤트의 뷰포트 좌표도 공유해 조준과 선택의 좌표 기준이 달라지지 않게 했다. 기존 이동 속도·가속·정규화 이동·발사 높이·발사 원점은 그대로다.
- 콘솔·거울에서 광선을 생성하지 않는다. 기존 `laser_system.gd`가 플레이어의 실제 `get_emitter_origin()`에서 광선을 추적한다. 반사·충돌·퍼즐 정답 계산은 수정하지 않았다.

## 직접 실행한 검증

기존 테스트와 새 테스트를 포함한 **16개 검증 묶음이 통과**했다. 새 `optical_control_test.gd`는 headless와 실제 OpenGL Compatibility 창에서 모두 실패 0건으로 완료했다. GPU 검수 자료는 `artifacts/remote_console.png`, `remote_hover_m2.png`, `remote_solution.png`다.

| 요청 항목 | 실행 결과 |
|---|---|
| 접근 없이 선택 | 발사 위치에 그대로 서서 로컬 회전 한계 4.5m보다 먼 M1/M2/M3를 화면 커서+E로 각각 선택 |
| 개별 회전 | 세 거울을 독립적으로 15°/1° 회전, 선택 변경과 강조 확인 |
| E 충돌 | 미연결 상태 원격 선택 실패, 콘솔 E 연결, 기존 튜토리얼·근접 E 테스트 통과, HUD/지도 위 E·휠 차단 |
| 광선 갱신 | 원격으로 -45°/+45°/+45°를 맞춘 후 기존 3회 반사 4구간으로 일반 수신기 활성 및 기존 문 개방 |
| 실제 발사 원점 | 첫 광선 실메시의 시작점을 휴대 발사기 원점과 비교. 플레이어를 0.4m 옮기면 원점도 같은 만큼 이동 |
| 조준 좌표 | 안정된 카메라에서 Godot 기본 투영과 비교, 카메라 복귀 중 화면→월드 왕복 오차 0.002m 이내 검사 |
| 기존 키 | 좌클릭 입력 상태를 사용한 발사, 제어 모드 안의 D 키 입력과 캐릭터 물리 이동, Tab/M, Esc 단계별 동작 확인. 기존 카메라 이동/튜토리얼 테스트도 통과 |
| 다른 방 제한 | 다른 방 권한 미부여, 카메라 안에 둔 다른 소유 거울 테스트 물체도 목록 검사로 선택 거부, 방 이탈 시 접근 차단 |
| 초기화 | 원격으로 바꾼 세 각도가 R로 0° 복원, 선택 해제, 콘솔 권한 유지. 재진입 재사용 및 전체 초기화 시 권한 제거 |
| UI | 선택 카드가 실제 화면 범위에 들어오는지 검사하고 GPU 캡처로 거울 번호·각도·조작 안내 확인 |

GUI 테스트 입력은 실제 창 픽셀과 논리 뷰포트 좌표의 `canvas_items` 배율을 구분해 주입한다. 대기 중 OS 커서/포커스가 자동 입력을 덮어쓰지 않도록 선택 검사 직전에 이벤트를 전달하고, 이동은 입력 상태를 읽는 실제 캐릭터 물리 함수를 호출해 확인했다. 이 결과를 사람이 전 과정을 장시간 수동 플레이한 결과로 간주하지 않는다.

제한된 headless 환경의 기존 인증서 저장소 경고 외 새 테스트의 스크립트 오류는 없었다. `git diff --check`도 통과했다.

## 남은 제한

권한은 현재 실행 세션/플레이 회차 안에서 유지된다. 다음 게임 실행까지 권한을 저장하는 기능이나 다른 방의 콘솔은 구현하지 않았다. 장시간 수동 조작, 모든 DPI/디스플레이 조합, 물리 멀티스레드 설정을 바꾼 환경까지 검수하지 않았다. 현재 포함 엔진과 프로젝트 설정에서 자동 입력·실제 물리·GPU 표시를 검증했다.
