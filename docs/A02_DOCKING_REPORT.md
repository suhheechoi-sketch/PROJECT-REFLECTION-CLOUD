## 실제 구현과 플레이

기존 `scenes/main.tscn`의 절차형 생성 구조를 유지했다. `scripts/a02_lab.gd`가 같은 벽·거울·수신기 생성 함수를 호출해 실제 물리 노드를 만든다. 새 고정 에너지 공급원은 없다. 장착된 L-07만 추가 광선 입력으로 연결하고, 장착 중 플레이어 발사기 보유/메시/발사를 끈다. 회수·재시도 때 장비를 반환하고 출력을 끈다. 콘솔 모드에서 WASD·휴대 발사를 정지하고, Esc/리셋 때 이전 카메라 위치·배율·cull mask 및 카메라 제어기를 복원한다. V 전환은 A02 조작에 사용하지 않는다.

A01 완료 후 기존 A 남쪽 서비스 개구부(x 약 -53, z=26)를 지나 남서쪽 셀로 이동한다. A02 콘솔은 (-81,38), 거치대는 (-78,39), 현장 레일 손잡이는 (-70,40.2) (모두 X,Z m). 콘솔 E → M1/M2 클릭 및 휠 조정 → Esc → 거치대 E → 제어 R 활성 → 현장 손잡이 E 후 휠 이동 → 최종 R 활성 → 거치대 E 회수. 거치대 근처 F는 지속 광선만 중지/재개한다. 콘솔과 레일의 선택·회전/이동은 UI 패널 아래에서 실행되지 않는다.

| 장치 | 월드 X,Z | 초기 / 해결 예 |
|---|---|---|
| M1 | -78,30 | 0° / 315° (-45°) |
| M2 | -70,30 | 0° / 45° |
| 레일 거울 | -73,35 → -70,35 | 45° 고정, X [-73,-70], 0.25m 단계 |
| 제어 R | -70,38.5 | 0.7초, 최종 R와 독립 래치 |
| 최종 R | -65,35 | 1.2초, 제어 R 활성 후 입력 허용 |
| 거치 발사 원점 | -78,1.15,39 (XYZ) | 북쪽으로 100% 조사 |

실제 광로 1: 거치 L-07 → M1 → M2 → 제어 R. 광로 2: 같은 발사기 → M1 → M2 → 이동한 레일 → 최종 R. 레일은 처음 광로 밖에서 대기한다. 채널의 실벽이 수신기 직사선을 차단하고 폭 0.5m 발사 개구부는 플레이어 전용 충돌층 8로 보행을 막는다. 벽은 반미터 격자 합집합의 외곽에만 생성한다. 광학 반사 횟수·특정 거울 ID를 수신기에 몰래 요구하지 않는다.

개발 진입: `godot --path . --script res://tests/play_a02.gd`. 일반 게임의 T01 시작은 유지한다. 이 진입은 개발을 위해 T/A01 완료를 설정하며 A02 해결 검증을 대신하지 않는다.

## 검증 결과와 제한

실제 설치 엔진은 `4.6.3.stable.official.7d41c59c4`. 저장소 기준 `4.7.2` 실행 파일은 제공되지 않았다. 엔진/프로젝트 렌더러 설정은 변경하지 않았다. 4.7.2 실행과 Windows PowerShell 검증은 미검증이다.

- 변경 전: 메인 게임 headless 부팅 및 기존 16개 `*_test.gd` 모두 종료 코드 0, 프로젝트 오류 없음. 최초 기본 홈 경로 실행은 저장 디렉터리 권한 때문에 중단되어 XDG 경로를 작업 디렉터리로 지정한 후 재실행했다.
- 변경 후: `VERIFY_REFLECTION.sh`로 메인 부팅과 17개 테스트(기존 16 + A02) 검증. 각 로그에서 종료 코드와 `SCRIPT ERROR`, `ERROR`, `FAIL`을 함께 확인한다. 로그는 무시된 `work/validation/`에 생성된다.
- A02 자동 검증: A01 선행 조건, 정확 장치 수, 실제 E·마우스 레이 선택·휠 회전·Esc 카메라 복귀, 콘솔 이동/발사 정지, 거치 장비 전환, 실제 두 반사 제어 R 해금, 잠긴 레일 거부, 현장 E·휠 이동과 범위 제한, 세 반사 최종 R/유지 시간, 각 거울 하나씩 제거 시 실패, F 중지/E 회수, 외부 직사격 표본 0 우회, 실제 캡슐 격자 탐색과 CharacterBody 이동 sweep으로 서비스 입구→각 조작 지점 연결, A01 R이 별도 거치 퍼즐을 훼손하지 않음, 로컬/전체 초기화의 장비·출력·레일 일관성.
- A01 기존 검사: 3회 실제 반사, 벽/문/벽 내부 발사, 우회 표본, 이동 캡슐, 클릭·휠·카메라·UI 회귀. 자산 해시, 튜토리얼, 진행, 지도, RGB/동시 수신, 에너지 테스트도 유지한다.
- 에디터 가져오기는 리소스 스캔을 마치지만 이 샌드박스가 TCP 디버거 소켓 생성을 막아 엔진 오류를 출력한다. 오류 없는 에디터 열기는 미검증이다. `VERIFY_REFLECTION.sh --import`는 해당 오류를 숨기지 않고 실패로 처리한다. 일반 검증은 가져오기를 선택적으로 분리한다.
- DISPLAY/Xvfb가 없어 GPU/Compatibility 실렌더 및 사람이 직접 마우스로 플레이한 검수는 미실시다. 그림/UI 가독성을 완성으로 보고하지 않는다. 자동 입력과 물리 테스트는 수동 플레이 검수가 아니다. 우회 검사는 유한 표본이며 모든 연속 좌표의 증명이 아니다.

## 남은 작업과 다음 순서

1. 기준 4.7.2 환경에서 에디터/전체 검증과 실제 시각 검수. A02 콘솔·거치·손잡이의 화면 가독성, HUD 여백·축척·벽 가림 검수. 필요 시 차폐 통로 메시 병합으로 벽 노드 수 최적화.
2. A03: 일반 거울 4 + 레일 1, 순서 R 2 + 일반 R + 선택 R-U. 순서 실패는 현재 퍼즐만 리셋. 실제 차폐 광로·직사격 방어 검사 후 A 복구 콘솔 READY → E를 추가하고 A01 조기 회로 복구를 제거한다. 그때 기존 테스트도 새 전체 경로를 따라 이동시킨다.
3. T04 검사 종료 단말기 E를 연결하고 H 목표/해금과 신규 A02/A03 게이트를 정합화. 현재 A02 완료 ID만 기록하며 A03 도어와 실제 다음 방은 없다.
4. B: 휴대 백색광 모드 해금으로 W-B02 필수 고정 광원 의존을 없애고, 첨부의 정확 거울/증폭기 수로 B01~03을 완성한다. 증폭 상한·RGB 에너지·복합 R·비인가 경로를 실레이로 검증한다.
5. C: C01 거울 2 및 동시 R, C02 제어/지속 R와 회전 차단막, C03 분기 2·차단막 2·동시 R·복구 E를 차례로 구현한다. 기존 B/C 조기 회로 콜백을 각 최종 복구 콘솔로 이동한다.
6. D 순서·기록 인증 → 선택 E 비상 회로 → F 한 발사기 종합 퍼즐/기본 엔딩. DIRECTOR는 안내·관찰만 담당하고 미확정 반전을 확정하지 않는다.
7. 전체 회로/수신기/순서/레일/발사기 소유·거치/출력/선택 경로를 버전 있는 저장 모델로 통합하고 재실행 후 해금·엔딩 유지 회귀 검사. 현재 지도 파일만으로 이 기준을 만족하지 않는다.

변경 파일은 Git diff/PR에 나열한다. 주요 구현은 `a02_lab.gd`, `main.gd`, `player_controller.gd`, `optical_control.gd`; 검증은 `a02_docking_test.gd`, 카탈로그 회귀, Linux/PowerShell 러너; 개발 실행은 `play_a02.gd`; 기준 동기화는 README/AGENTS/LEVEL_DESIGN/DEVICE_CATALOG/통합 지시서/본 보고서다. 기존 미추적 `.uid` 파일과 엔진·캐시·잠금 아트는 포함하지 않는다.
